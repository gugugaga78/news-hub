附：国内可达性实测（2026-10-25）

测试方法：本机 Invoke-WebRequest，走系统网络
测试时本机代理状态：已开启（127.0.0.1:7890，Clash/FlClash）
所以下表「200」的含义是「你的机器现在这个网络环境下能打开」，不是「裸连能开」

一、结论先说（避免误判）

同样一个 HuggingFace，两种测法两种结果：

测法结果原因
本机浏览器 / curl / Invoke-WebRequest✅ 200走系统代理 127.0.0.1:7890
采集 agent 的 web_fetch 工具❌ 失败 7 次不走系统代理

所以你看到「HuggingFace 能开」是因为你开着 Clash。关掉代理就开不了。

这不是谁的错，是路不一样。下面把两类结果分开记。

三、不依赖代理的方案（关掉 Clash 也能用）

如果你哪天不想开代理，这几条路照样通：

  1. huggingface.co 打不开 → 用 hf-mirror.com

下载模型时设环境变量：HF_ENDPOINT=https://hf-mirror.com

  1. GitHub 打不开 → 用 cdn.jsdelivr.net

例：https://cdn.jsdelivr.net/gh/archlizheng/AIPM-Wiki@main/README.md

这个 CDN 实测 200，比 raw.githubusercontent.com 稳

  1. Paper with Code 已下线 → 用 HuggingFace Papers 或 arXiv 直接搜
  2. LMArena 打不开 → 用 Artificial Analysis（200）看榜单

结论：能真正订阅的只有 3 个（量子位、Jack Clark、Simon Willison）。其他只能手动刷网页。

五、这份实测的边界

  • 时间是 2026-10-25 晚，网络环境会变
  • 代理状态：测时开着 Clash，关掉后结果会不同（见第三节的替代方案）
  • agent 的 web_fetch 与你的浏览器走不同网络栈，两者结果不一致是正常的，不要以为是哪个测错了
  • LMArena 的 403 可能是 Cloudflare 的机器人校验，浏览器手动打开也许能进——如果你要用它，自己开浏览器试一次
