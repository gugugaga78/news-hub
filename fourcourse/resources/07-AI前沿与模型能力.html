AI 前沿与模型能力 · 信息源清单

用途：持续跟踪，不是一次性读完
采集日期：2026-10-25
采集对象：谭梓琦（重庆理工大学 管理学院 数智管理 大二）· 方向 AI 产品 / AI Agent
采集纪律：下列每一条链接都用 web_fetch 实际发起过请求，并记录真实 HTTP 状态或失败原因。
全程发起 66 次 web_fetch 请求、覆盖 60 个不同 URL（其中 6 次为对失败项的重复请求，用于区分「偶发失败」与「真不通」）。
打不开的一律不伪装成可用，集中列在「六、验证记录」并如实标注需代理 / 需登录 / 已下线。
没有编造任何一条链接、RSS 地址或更新频率。

使用前提：这份清单是「入口」，不是「读物」

你要的是能持续跟踪 AI 前沿的入口。所以这份清单的筛选标准只有三条：

  1. 能验证——今天点开有内容，不是空壳或 404
  2. 能订阅——有 RSS / 邮件 / 固定栏目，不用你每天主动想起它
  3. 有增量——每周真的有新东西，不是三个月没动的静态页

不满足这三条的，哪怕名气再大，也只在「验证记录」里留一行失败说明。

一、模型能力榜单

这一类的价值不是「谁第一」，是能力/价格/速度的取舍曲线——你做 AI 产品，选型的依据在这里，不在新闻里。
#名称链接类型语言需代理更新频率一句话说明
1Artificial Analysishttps://artificialanalysis.ai/独立评测榜单（智力/速度/成本三维）英文❌ 国内可直连（实测 200）近乎每日（首页 changelog 可见 10-23、10-22、10-19、10-18…连续条目）最值得每周看的一个。它的 Intelligence Index v4.3.2 由 10 个评测合成（GDPval-AA、Terminal-Bench 4.0、SciCode、Humanity's Last Exam、AA-LCR 等），并且同时给跑完一整套 benchmark 的总花费（如 Gemini 4 Argon 高配 $2,407、Claude Opus 5.5 高配 $8,708）。对你直接有用的是「Intelligence Index vs. Cost per Task」象限图——一眼看出哪个模型在性价比前沿上。它还自己写模型发布分析文章（如 Kimi K3.1 Pro 上线即第 4）。
2OpenRouter Rankingshttps://openrouter.ai/rankings真实调用量排行榜（市场份额/开发者实际选择）英文❌ 国内可直连（实测 200）滚动窗口：日 / 周（页面顶部有 week 视图切换）跟「评测榜」互补的关键一环：这里排的不是分数，是真金白银的 token 消耗。板块覆盖 Top Models、按任务类型的支出、单会话成本、开源 vs 闭源份额、按自然语言/编程语言/上下文长度/工具调用的分布。做产品时判断「开发者真的在用谁」看这个，比看 benchmark 靠谱。

4FlagEval（智源研究院大模型评测）https://flageval.baai.ac.cn/中文机构评测榜单（多模态/多维度）中文❌ 国内可直连（实测 200）未在首页确认更新周期，按评测项目批次发布北京智源研究院的评测平台，与 SuperCLUE 互为交叉验证——两个中文榜单结论一致时才可信，只信一个容易被单一评测口径带偏。⚠️ 同为 JS 渲染，浏览器打开看。
5LMArena（原 Chatbot Arena / LMSYS）https://lmarena.ai/人类盲测偏好榜（Elo）英文✅ 需代理（实测 6 次全部 fetch failed，含 /leaderboard 与 chat.lmsys.org）持续滚动（无法实测，据其机制为实时对局累积）原本是「人类投票偏好」这条线的标杆。国内网络打不开，已确认不是偶发——DNS/连接层面失败。要用得挂代理。因此本次没把它算进「可用入口」，只在验证记录里保留。
6HuggingFace Open LLM Leaderboardhttps://huggingface.co/spaces/open-llm-leaderboard/open_llm_leaderboard开源模型榜单（社区维护）英文✅ 需代理（huggingface.co 全域实测 7 次 fetch failed）—原本是开源模型横评的主入口。整个 huggingface.co 域名在国内直连不通（详见第六节）。替代方案见「五、开源模型」的 hf-mirror。
7C-Eval（中文基础模型评测套件）https://cevalbenchmark.com/中文学科知识评测（52 学科 / 13948 题）中文✅ 需代理 / 域名解析失败（实测 3 次，含 http 与 leaderboard_zh 页，全部 fetch failed）榜单更新慢（学术项目，非运营型）学术界（上交 + 清华，NeurIPS 2023）的中文评测套件，覆盖面比 SuperCLUE 更偏「学科知识」而非「对话能力」。官网打不开，但 GitHub 仓库可访问：https://github.com/hkust-nlp/ceval （实测 200）——想看题库构成、自己跑分，从仓库走。

给你的取舍建议：日常只盯 Artificial Analysis（能力+成本）+ OpenRouter（真实选择）；涉及国内落地再加 SuperCLUE + FlagEval 交叉验证。LMArena 那套「人类偏好 Elo」的结论，Artificial Analysis 和 OpenRouter 已经能部分替代，不值得为它专门挂代理。

二、论文入口

你的目标是「能判断能力边界」，不是复现。所以入口要能筛，不是给你 842 篇让你自己捞。
#名称链接类型语言需代理更新频率一句话说明
1arXiv cs.CL（计算与语言学）recenthttps://arxiv.org/list/cs.CL/recent预印本分类页（每日新投稿列表）英文❌ 国内可直连（实测 200，返回完整列表）每工作日更新（实测当天列表含 Fri 23 Oct / Thu 22 Oct / Wed 21 Oct / Tue 20 Oct / Mon 19 Oct 五天，总计 842 条）你的主论文入口。cs.CL 是 LLM / Agent / RAG / 对齐 / 评测的主战场。用法：只看标题 + 摘要首句，每天 30 秒扫完 50 条，一周下来你对「大家在解决什么问题」就有手感了。每条都有 PDF / HTML / 格式页三个直链，HTML 版可直接浏览器读不用下 PDF。
2arXiv cs.AI（人工智能）recenthttps://arxiv.org/list/cs.AI/recent预印本分类页英文❌ 国内可直连（实测 200）每工作日更新（实测当天总计 1421 条，比 cs.CL 更杂）cs.AI 覆盖面更宽（含规划、多智能体、知识表示、机器人交叉），噪音也比 cs.CL 大。建议：只在找「Agent 架构 / 多智能体协作 / 工具使用」这类题目时来扫，日常以 cs.CL 为主。

4Cool Papers（papers.cool）https://papers.cool/arxiv/cs.CL中文友好的 arXiv 每日论文聚合（带 Kimi 一键解读）中英混排（界面中文）❌ 国内可直连（实测 200，返回完整摘要正文）每日（实测页面标注 2026-10-23，Total: 117，条目按投稿时间排序）中文网络环境下最省事的每日论文入口。把 arXiv 当天全部论文按编号列出，每条直接给完整摘要，并挂 [PDF] [Copy] [Kimi] [REL] 快捷按钮——点 Kimi 可以让模型直接解读这篇。在国内这是比 HuggingFace Daily Papers 更好的替代品（后者需代理）。
5HuggingFace Daily Papershttps://huggingface.co/papers社区每日精选论文（带投票排序）英文✅ 需代理（实测 7 次 fetch failed）—原本是「社区帮你筛过一遍」的日榜，质量不错。国内打不开。替代：Cool Papers（上面第 4 条）+ alphaXiv。
6Papers with Codehttps://paperswithcode.com/论文↔代码↔榜单关联库英文✅ 已下线（实测：请求被跨域 301 跳转到 https://huggingface.co，站本身已不存在）—这个站已经没了。 它被 Hugging Face 收购后并入 HF，原域名直接跳转 huggingface.co。而 HF 国内又不通——两头堵，彻底不可用。别再收藏它了，找「某篇论文的官方代码」改从论文里的 GitHub 链接或 alphaXiv 走。

1HuggingFace 模型库（国内镜像 hf-mirror）https://hf-mirror.com/模型/数据集权重库（镜像）英文（含中文模型卡）✅ huggingface.co 本体需代理（实测 7 次 fetch failed，含 /models、/papers、models?sort=trending）；❌ 镜像 hf-mirror.com 国内可直连（实测 200）跟随 HF 实时同步这条是你最关键的一条。整个 huggingface.co 域名国内直连不通，但 hf-mirror.com 是可用镜像（公益项目）。用法实测有效三条：①网页搜索后在模型页 Files and Version 直接下；②export HF_ENDPOINT=https://hf-mirror.com（Windows：$env:HF_ENDPOINT = "https://hf-mirror.com"）后正常用 huggingface-cli download；③用它的 hfd.sh（基于 aria2，断线续传）。⚠️ Gated 仓库（如 Llama 系列）仍需先上 HF 官网申请许可拿 Access Token，镜像站不支持登录。
2ModelScope 魔搭（阿里）https://modelscope.cn/models国内模型库 + 数据集 + 在线体验中文❌ 国内可直连（实测 200，速度稳）跟随模型发布（国内模型首发常在此）国内跑模型的第一选择，不需要任何代理。优势：①Qwen / GLM / 各类国产开源模型的首发地（Qwen 每次发布都同时挂 HF 和 ModelScope）；②有在线 Notebook 和创空间可直接试，不用本地配环境；③下载速度是 HF 的十倍级。你如果只是「想跑起来看看」，从这里起步最省事。
3Ollama 模型库https://ollama.com/library本地部署模型库（一条命令拉取）英文❌ 国内可直连（实测 200，返回完整模型列表与拉取量）滚动更新（实测列表可见 gemma4「1 week ago」、qwen3.5「1 week ago」、gpt-oss「2 weeks ago」等近期更新标记）本地试模型的最短路径。列表按 Pulls 排序（实测前列：llama3.1 120.6M、deepseek-r1 94.2M、qwen3 41.5M、gemma4 27.8M、qwen3.5 23.3M、gpt-oss 14.2M），每个模型页标了参数规模、能力标签（tools / thinking / vision / cloud）和最后更新时间。做 AI 产品原型验证时，ollama run qwen3.5 就够了，不必碰 API 计费。
补充：OpenAI 也把开放权重模型放出来了（gpt-oss 20b / 120b，Ollama 库实测在列）——说明「开源」这条线上美国厂重新入场了，值得留意。

七、每周跟踪方案（10 分钟看完一轮的最短路径）

原则：固定时间、固定顺序、固定动作。不靠「想起来才看」，靠流程。
建议固定周日晚上 21:00，手机/电脑都行。

每轮 10 分钟 · 五步（附时间预算）

步时间打开什么只看什么产出
13 minhttps://artificialanalysis.ai/首页 Intelligence Index 榜单 →「前 5 名有没有换人」+ 点开 "Intelligence vs Cost per Task" 象限图看新面孔落在哪个位置记一行：这周有 N 个新模型进了前 10，其中性价比象限里的是 ___
22 minhttps://openrouter.ai/rankingsTop Models 榜 →「调用量份额 Top 5 有变化吗」记一行：开发者真在用谁（和榜单是否一致，不一致就是信号）
33 min阅读器里的 量子位 RSS（https://www.qbitai.com/feed）只扫标题，不点开。看到「模型发布 / 能力突破 / 价格变动」三个关键词才点记 1-3 条标题进你的周记
41 min阅读器里的 Simon Willison Atom（https://simonwillison.net/atom/everything/）只看有没有带 llm-release 或 llms 标签的新条目，挑 1 篇大概率能找到一篇「他上手实测新模型」的短文，链接存进待读
51 min阅读器里的 Import AI RSS（https://jack-clark.net/feed/）只读本期第一条的「Why this matters」那一段一段判断，够了。整期留到月度

合计 10 分钟。 关键是第 3 步「只扫标题不点开」——一旦点开一篇就要 10 分钟，节奏就崩了。

每月 1 次 · 60 分钟（深度轮）

  1. 30 min：挑一期 Import AI 完整读（https://jack-clark.net/）。不要读最新的，读你觉得「离你产品最近」的那期。重点看它怎么写「数字 + 为什么重要」——这是你写产品论证要用的写法。
  2. 15 min：https://papers.cool/arxiv/cs.CL 翻两周前的（不是今天的），挑 2 篇摘要读透。隔两周再看，能过滤掉当时的炒作噪音。
  3. 15 min：读一篇 AI 科技评论 的长文（https://www.leiphone.com/category/ai），补产业视角。

每季度 1 次 · 2 小时（校准轮）

唯一目的：把这份清单里失效的源换掉。

  1. 逐条点一遍本文所有链接，记录哪些 403/404/停更
  2. 更新「六、验证记录」的日期与结论
  3. 问自己一个问题：过去三个月，这份清单里有哪 3 个源我一次没打开过？ 删掉它们——留着只会让清单变重
  4. 如果某个源连续两个季度「打开但没收获」，降级处理，别自我欺骗说「以后会用」

一个反直觉的建议

别订阅超过 6 个源。 上面中文 4 + 英文 3 已经是上限。信息源的边际收益递减得非常快——第 7 个源带来的新增信息量接近于零，但它会占掉你本来用于「读透一篇」的时间。

宁可少订，读透一个。 一个把 Import AI 连续读 20 期的人，对 AI 能力边界的判断力，远胜于订了 30 个源每天刷标题的人。
