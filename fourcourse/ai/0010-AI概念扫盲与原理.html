AI 第 10 课概念扫盲 + 原理讲解

2026-10-25 · 建议 90 分钟分两次看完 · 前置：已读完李博杰第 1-3 章
🧭 这一课解决什么问题：你说「概念了解，原理和运用不熟」。这很典型——概念是名词，原理是因果。名词可以背，因果必须推。

所以这一课分两轮：第一轮把容易混的名词划清边界，第二轮讲清「为什么是这样」。学完你应该能对任何一个 AI 现象说出「这是哪个机制导致的」。

第一轮：概念扫盲（把边界划清）

1. 层级关系 —— 最容易在同句话里混用的五个词

AI（人工智能）⊃ ML（机器学习）⊃ DL（深度学习）⊃ LLM（大语言模型）
Agent（智能体）= LLM + 工具 + 记忆 + 循环 ← 它是系统，不是模型
词准确含义边界在哪
AI所有让机器表现出智能的方法包括规则引擎（比如早期的象棋程序），不一定是"学习"出来的
ML从数据里学规律，而不是人写死规则垃圾邮件过滤器用统计方法也算 ML
DL用多层神经网络做 ML层数多 ≠ 一定更好
LLM用 Transformer 架构 + 海量文本训练的大模型LLM 是 DL 的一种，不是所有 DL 都是 LLM（图像分类模型不是）
Agent让 LLM 自主决策、调用工具、循环直到完成任务的系统Agent 不是模型。同一个模型可以做成不同 Agent，能力可能差很多
⚠️ 最常见的错误：说「这个 Agent 很聪明」。准确说法是「这个模型能力够，而且工具和循环设计得好」。「Agent 变强」不等于「模型变强」——这两件事的改进成本差几个数量级。

2. 训练 vs 推理 —— 成本差 100 倍的两件事

训练（Training）推理（Inference）
做什么调整模型参数，让它学会规律用固定参数算出输出
成本一次几百万美元一次几厘钱
谁在做OpenAI / DeepSeek / 阿里这些公司你和我
能不能改改完参数永久变了不改任何参数

关键推论：你调用 API 时，模型参数一点没变。所以「怎么让它记住我的偏好」这类问题，答案永远在上下文里，不在参数里。

3. 让模型变好的五种手段（按成本从低到高排）

手段改什么成本什么时候用
1. Prompt 工程你输入的指令几乎为零永远先试这个
2. RAG外挂知识库，检索后塞进上下文低（建库+检索）知识缺失时——模型不知道你的文档
3. 工具调用给它能查、能算、能执行的手中（写工具）能力不足时——它不会算精确数字、不能联网
4. SFT 微调参数（小规模再训练）高行为不对时——格式、语气、固定流程
5. RLHF / RL参数（偏好或推理优化）很高推理不行时——数学、代码、复杂决策
判断口诀：知识缺失 → RAG　｜　行为不对 → 微调　｜　能力不足 → 工具
💡 这道题面试常问：「模型回答不了我们公司的产品问题，怎么办？」
答「微调」= 不及格。正确答案是 RAG——这是知识缺失，不是行为问题。微调贵、慢、还会遗忘。

4. 模型的"身体"：参数、层、Token、上下文窗口

  • 参数（权重）：模型学到的数字，从几十亿到几万亿个。它是"知识"的存储形式，但不是人能读的文本
  • 层（Layer）：参数的堆叠结构，越深表示抽象层次越高
  • Token：文本的最小处理单位。英文约 1 token ≈ 0.75 词；中文约 1 字 = 1-2 token
  • 上下文窗口（Context Window）：模型一次能"看到"多少 token。这是硬限制，不是它"记性不好"
📝 直观换算：一本 20 万字的中文书 ≈ 30-40 万 token。所以"把整本书塞进去"在 128k 窗口下做不到——这就是为什么需要 RAG 切片检索。

5. 三个最容易混的"给模型信息"的概念

概念是什么生命周期例子（Hermes 里）
Prompt你这一次输入的指令这一次对话你打的字
Context模型这一次能看到的全部内容：系统提示 + 历史对话 + 检索结果 + 工具返回这一次对话system prompt + 对话历史 + 工具定义
Memory跨会话保存的信息，存在模型外面，用时才塞进 Context长期Hermes 的 memory 文件
⚠️ 这三者的关系是：Memory 和 RAG 检索结果，最终都要变成 Context 的一部分。所以 Context 窗口不够用时，再好的记忆系统也塞不进去——这就是「记忆管理」要解决的问题（你书上第 3 章）。

6. 向量与检索：RAG 的地基

文本 → Embedding 模型 → 一串数字（向量，比如 1024 维）
语义相近的文本 → 向量在空间里距离近
余弦相似度 = 算两个向量的夹角，越接近 1 越相似

RAG 的完整流程：

  1. 把文档切成块（chunk）
  2. 每块用 Embedding 模型变成向量，存进向量库
  3. 用户提问 → 问题也变成向量
  4. 在向量库里找最相似的 K 个块
  5. 把这 K 个块塞进 Context，让模型"基于它们"回答
💡 一句话理解 RAG：不让模型"回忆"，让它"抄"。 模型回忆会编，抄材料不容易编。

7. 行为层概念

词含义为什么重要
幻觉编造看似合理但不存在的内容不是 bug，是概率生成的必然结果（下面原理 2 详讲）
对齐（Alignment）让模型的行为符合人类意图和价值观RLHF 就是干这个的
温度（Temperature）控制输出随机性。0 = 几乎确定，1 = 发散要准确用低温，要创意用高温
越狱（Jailbreak）用特殊提示绕过模型的安全限制说明安全对齐是"学出来的"，不是"写死的"

8. 怎么衡量好坏

  • Benchmark：标准测试集（如 MMLU 考知识、GSM8K 考数学、HumanEval 考代码）
  • Elo 分：两两对比投票算相对强弱（LMArena 用这个）
  • 没有万能榜单：模型 A 在数学上强，不代表它写文案也强。选型要看你的具体任务

第二轮：原理（为什么是这样）

原理 1：LLM 到底在算什么

给定前面所有的词，预测下一个词的概率分布

就这么一件事。不是"理解"，不是"思考"，是对海量文本统计规律的高维拟合。

但为什么它看起来像理解？

因为要准确预测下一个词，模型被迫学会了语法、事实关联、甚至推理链条。举例：要预测「张三比李四高，李四比王五高，所以张三比王五___」的下一个词，模型必须隐含地完成传递性推理。这不是被教会的，是为了降低预测误差而涌现的能力。

⚠️ 这个原理直接解释了三个现象：
① 它会一本正经胡说（概率高 ≠ 事实对）
② 换个问法答案会变（概率分布被扰动）
③ 它不知道"自己不知道"（训练数据里少见"我不知道"这种回答）

原理 2：幻觉不是 bug，是必然

三个成因，缺一不可：

  1. 训练目标错位：模型学的是"像人写的文本"，不是"说真话"。人类写的文本里，流畅 ≠ 真实
  2. 没有"未知"这个概念：模型对所有问题都会给出一个概率分布。它没有"这个我没学过"的输出通道
  3. 采样有随机性：temperature > 0 时，它会从概率分布里采样，低概率的答案也可能被选中

所以对策也是三条，一一对应：

成因对策
训练目标是"像人写的"要求它引用来源，有出处的才是可核查的
没有"未知"通道在提示词里明确允许它说"我不知道"，并给出判断标准
采样随机事实型任务把 temperature 调到 0
💡 最有效的一招是给它材料（RAG）：把"回忆"变成"抄"。抄错了你能看出来，回忆错了你看不出来。

原理 3：上下文窗口为什么有限（这是数学，不是工程偷懒）

Transformer 的核心是自注意力：每个 token 要和序列里所有其他 token 算相关性。

计算量 ≈ O(n²)　（n = 序列长度）

上下文翻倍，计算量翻四倍。所以：

  • 长上下文很贵：不是存储贵，是计算贵
  • 长上下文里"中间的信息"容易被忽略：这叫 lost in the middle，是实测现象——模型对开头和结尾更敏感，中间段落容易被跳过
📝 这解释了你书里第 2 章讲 KV Cache 的意义：把已经算过的注意力结果缓存下来，避免重复计算。也解释了为什么 Agent 必须做"记忆压缩"——不是省钱，是不压缩就装不下。

原理 4：Agent 为什么能工作（补三个短板）

LLM 有三个硬短板，Agent 用三样东西补：

LLM 的短板Agent 的补法对应 Hermes 里的东西
不能查、不能算、不能操作外部世界工具（Tools）terminal / web_fetch / 各种 MCP
不能跨会话记住你记忆（Memory）memory 文件、学习记录
一次想不清楚复杂任务循环（ReAct）：想→做→看结果→再想agent 主循环
Agent 能力上限 ≈ 模型能力 × 工具质量 × 循环设计

注意这是乘法不是加法。任何一项接近零，整体就接近零。工具写错，模型再强也没用。

原理 5：Agent 为什么会失败（四种典型死法）

死法机制怎么防
错误累积第 3 步错了，后面全在错的基础上继续分步验证、设 checkpoint、关键步骤人工确认
上下文污染错误信息进了 Context，模型把它当真前提工具返回要结构化、明确标记成功/失败
工具误用选错工具、参数填错工具描述写清"何时不用"（第 4 章）
目标漂移做着做着忘了原始目标每次循环把原目标重复一遍
⚠️ 这四条正是你书上第 6 章「Agent 评估」要解决的问题。评估不是打个分，是定位死在哪一步。所以要做"分步评估"，不只是端到端看结果。
